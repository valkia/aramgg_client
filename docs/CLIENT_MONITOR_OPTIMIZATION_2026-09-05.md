# 启动窗口与英雄监控优化 · 2026-09-05

基于 `431a93d` / `0.2.15` 的本地修复，尚未提交、打包发布或进行 Windows 对局实测。此前审查报告是修复前的基线；本次修复 A2、B3，并保留 B2 中四个必要窗口的启动预加载。

## 影响判断

这是值得处理的中等优先级问题。主窗口原先每两秒重新查询选人快照，必要时再调用英雄查询，有英雄时写入相同缓存，并在英雄变化时重复请求详情展示。主进程本身已有相应职责，因此这些持续操作可以去掉。慢 IPC 还可能造成重叠；首次 IPC 完成前停止，可能反而在其完成后重新创建轮询定时器。

四个窗口都承担必要功能，提前创建可以减少游戏中首次展示时等待页面加载的延迟。按用户对即时显示的要求，最终保留启动时预加载四个窗口；常驻窗口数量不减少，也不据此承诺 CPU、内存、温度或电量的降幅。优化集中在重复请求、写入和异步生命周期。

## 变更

| 项目 | 修复后的行为 |
| --- | --- |
| 应用启动 | 创建主窗口，并提前加载英雄详情、海克斯顶部浮窗和右侧面板；三个辅助窗口保持隐藏。 |
| 英雄详情 | 启动完成后复用已就绪的窗口，选人或用户预览时展示；显示仍遵守用户偏好。 |
| 海克斯浮窗/侧栏 | 启动时均已准备，即使当前关闭显示也保留预加载；启用后复用，不在游戏中首次创建。窗口意外销毁时有重建入口。 |
| 首次消息 | 只有 renderer 完成语言初始化、路由加载、Vue 挂载与事件监听后，才发送首条展示数据。就绪信号通过受信任 IPC 接收。 |
| 并发窗口请求 | 共享创建中的 Promise；原生窗口已存在但页面尚未就绪时也继续等待，避免重复创建或丢失消息。失败后清理并允许重试。 |
| 英雄监控界面 | 初始读取一次缓存状态，再订阅主进程事件；移除每两秒的额外轮询、缓存写入和重复的胜率/详情请求。 |
| 停止/恢复 | 停止会解除当前界面的状态订阅，迟到响应不再生效；恢复会重新读取并订阅。与原来一样，按钮不关闭独立的主进程 gameflow/OCR 服务。 |
| 英雄持久化 | 主进程和已有 LCU 读取路径通过同一去重函数写入；值未变化时不调用 store.set。 |
| 主进程轮询 | 上一轮未完成时不启动下一轮；结束/切换阶段后，旧选人或窗口加载结果不会重新弹出过期详情。 |

没有改动 LCU 操作权限、推荐范围、数据语言准备顺序、截图频率或 OCR 匹配算法。Firebase 的静态导入不属于本次修复；其它审查条目仍需单独处理。

主要实现位于 [主进程状态](/Users/a111/Workspace/projects/aramgg_client/src/main/modules/champion-monitor-state.ts)、[界面订阅](/Users/a111/Workspace/projects/aramgg_client/src/renderer/components/ChampionMonitor.vue)、[窗口管理](/Users/a111/Workspace/projects/aramgg_client/src/main/modules/window-manager.ts)、[窗口创建合并](/Users/a111/Workspace/projects/aramgg_client/src/main/modules/lazy-window.ts)和[页面就绪等待](/Users/a111/Workspace/projects/aramgg_client/src/main/modules/renderer-ready.ts)。

## 验证

新增 21 个行为测试，覆盖实际主进程初始化/轮询代码、Vue 组件订阅、窗口管理器、创建合并和首条 OCR 消息；Electron、LCU 与本地状态均使用隔离替身。

- 模拟一分钟主进程持续监控同一个英雄，只写一次英雄缓存、只请求一次详情展示。
- 模拟一分钟主窗口运行，只读取一次初始状态，后续从事件更新；没有额外快照、英雄、胜率或写缓存请求，也没有轮询 timer。
- 初始响应落后于推送、停止/卸载后响应迟到、停止再恢复均不会覆盖新状态或恢复旧订阅。
- 慢 gameflow 请求不重叠；选人窗口加载期间进入结束阶段，不展示过期详情。
- 启动预加载全部四个窗口，辅助页面全部就绪后才开始游戏监控；辅助窗口初始隐藏，启用后复用原窗口。
- 并发请求只创建一个原生窗口；页面 load 完成但 Vue 未就绪时不交付消息。
- 页面加载失败、关闭或未发出就绪信号时有清理；服务停止后，不发送正在等待窗口加载的 OCR 结果。
